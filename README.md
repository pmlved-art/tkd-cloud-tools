# TKD Cloud Tools

Початкова перевірка мережевого доступу для приватного середовища ТКД.
Цей пакет НЕ надає доступу до замовлень і НЕ змінює сайти.

## Запуск

Потрібен Python 3.9 або новіший, сторонніх залежностей немає.

```sh
python3 -m unittest discover -s tests -v
python3 scripts/preflight.py --site tkd
```

Для чотирьох сайтів: `python3 scripts/preflight.py --site all`.
Скрипт виконує лише анонімні GET-запити до публічного WordPress REST index,
перевіряє TLS, не переходить за редиректами, не читає cookies або паролі.
Дозволені хости перелічені у `scripts/preflight.py`; їх потрібно дозволити
в мережевих налаштуваннях хмарного середовища. Якщо інфраструктура вимагає
явного проксі, потрібне окреме перевірене налаштування клієнта.

`public_index_reachable` означає тільки доступність публічного API.
`application_passwords_advertised` означає лише наявність оголошення
механізму автентифікації. Жоден із показників не підтверджує доступу до бази.
403/помилка мережі потребує перевірки доступу, а не вимкнення TLS чи захисту сайту.

## Далі: підключення робочих даних

1. Через авторизований канал звірити актуальний код власного модуля ТКД.
   Локальна копія використовує `tkd_order`, `_tkd_order_number`, `_tkd_status`.
   Не прирівнювати її до стандартних замовлень WooCommerce.
2. Виявити або підготувати вузький API читання одного замовлення. Не відкривати
   всі метаполя, реквізити та дані клієнтів через загальний REST endpoint.
3. Створити окремого технічного користувача з мінімальними правами і відкличний
   Application Password. Не використовувати основний пароль адміністратора.
4. Зберегти доступ у захищених налаштуваннях хмари, обмеживши точним HTTPS-хостом.
   Авторизований клієнт має забороняти редиректи та приховувати секрети у логах.
5. Перевірити відмову без ключа/без прав, читання конкретного замовлення,
   відповідність базі й відкликання ключа. Потім перевірити з телефона без Mac.

Зміни оплат, резервів та відвантажень потребують окремих операцій через чинну
бізнес-логіку: блокування редактора, перевірку версії, ідемпотентність і аудит.
Цей пакет таких операцій не реалізує.

Документація: https://developer.wordpress.org/advanced-administration/security/application-passwords/
