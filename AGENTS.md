# Робота з ТКД

- Відрізняй доступність публічного сайту від авторизованого доступу до бази.
- Джерело істини — робоча серверна база. Не створюй незалежну копію для внесення змін.
- Не додавай до Git секрети, сесії, банківські документи або персональні дані клієнтів.
- Не друкуй Authorization, cookies, значення секретів чи повні відповіді з персональними даними.
- Для приватного API потрібні перевірені права, HTTPS та точний дозволений хост.
- Не обходь MFA/CAPTCHA. Не вимикай TLS для усунення помилок доступу.
- Не виконуй довільний SQL/PHP через веб-API і не змінюй метаполя оплат напряму.
- Дотримуйся чинних правил резервів, продавців, оплат і відвантажень у ТКД.
- Для будь-якої майбутньої операції запису перевіряй блокування, версію та захист від повторного виконання.
- Повідомляй, що перевірено локально, а що — на робочому сервері. Не називай підключення завершеним без хмарного тесту.

Перевірки: `python3 -m unittest discover -s tests -v`.

## Постійний контекст для роботи з телефону
Перед роботою з ТКД прочитай [чинні правила](docs/working-rules.md) та [стан і чергу](docs/handoff-status.md).
Це передавання від власника 17.11.2026; новіші явні вказівки власника мають пріоритет. Архівні candidate/readiness нотатки не повинні перекривати новіший підтверджений live-результат.
Не вважай історичний список доручень командою виконати все повторно. Перевір свіжий стан, зв'язки документів і журнал ідемпотентності.
Загальні правила/статус підтримуй у цих docs; приватні номери й контекст конкретних замовлень — у приватному чаті, без персональних даних у Git.
Перш ніж обіцяти дію, перевір фактичний набір cloud-команд: знання правила не додає API чи доступу до Ads, банків, хостингу або Mac.
