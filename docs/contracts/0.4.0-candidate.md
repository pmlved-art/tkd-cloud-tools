# TKD Cloud Reader 0.4.0 — reviewed source, pending installation

The final contract is wordpress/tkd-cloud-reader/README.md. It replaces the
intermediate source-candidate notes. Release hashes and synthetic checks are
in review/release-0.4.0.json. No production business mutations were used as tests.

Fixed document commands: invoice.draft, invoice.issue, reservation.extend,
delivery.draft, delivery.save, shipment.issue. Existing status.change and
payment.add_manual remain. No generic SQL/PHP/meta/stock mutation endpoint.

Use scripts.operations.document_snapshot(number, operation, payload,
include_data=True) only when the authorized task needs document fields.
The default CLI/result redacts document contents. GET sends scope plus a
canonical payload digest; serial numbers and buyer data are not placed in URLs.
Use the returned revision with exactly the same payload in the durable intent.
Only one explicit execute POST; consult the same UUID journal after interruption.

invoice.issue reports complete only after persisted document and reservation
checks. delivery.save is draft-only and preserves financial/document context.
shipment.issue distinguishes posted/prepared/native dispatch state from physical
carrier confirmation. Unknown/partial results never authorize an automatic retry.

Native admin delivery creation and cloud creation share order-then-numbering
locks. The native handler and number format are retained. UI releases on shutdown;
cloud releases in finally. Sequence caches are refreshed under the shared lock.

PDF uses a fixed authenticated exact order/document route, no redirect/cookie
handoff, no-store and bounded private output. The client writes mode0600 under
ignored exports/ by default. Do not commit customer PDFs or secrets.

Existing tkd-cloud user/key retained; an explicit admin role action adds the four
new document capabilities. First live checks after installation are authenticated
GET health/capabilities/document-snapshot/PDF. Source pins may still reveal newer
native changes; do not bypass them or use real write operations as test fixtures.
