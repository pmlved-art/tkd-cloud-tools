## Routes and fixed schemas

Existing health, minimal/details/lookup/stock/manifest, status/payment operations
and GET journal remain. New domain operations share POST /operations and its
six-field envelope operation_id/operation/order_id/number/revision/payload.
New exact order GET /orders/{number}/document-snapshot takes only operation and
JSON payload query params. Supply the same payload as the later explicit intent.
Snapshot returns revision, order_id, linked document IDs/types, native_edit_post,
editor_locked and preview_is_acceptance:false. It performs bounded stored reads,
no native draft-ensure, manager_snapshot, fiscal/scanner/provider getters or nonce.

Payloads (no extra keys):
- invoice.draft: {}. Full native ensure_manager_draft, no weaker issued shortcut.
- invoice.issue: {invoice_id: positive integer, number: bounded invoice number,
  date: canonical YYYY-MM-DD}. Full save_invoice with stored seller/bank and ALL
  ten buyer fields, preserved under strict text bounds. Nonces created after
  durable claim. Scoped wp_die/POST restoration, exact persisted document checks.
- reservation.extend: {hours:36|48|72}, integer only. Pinned total helper defines
  start+duration; no now-relative extension, no mark-paid/release/cancel shortcuts.
- delivery.draft: {invoice_id:positive integer}. Fixed extraction of pinned
  create_from_invoice semantics; issued/paid exact active invoice, exact remaining
  quantities (scale3), existing drafts count toward allocations. No generic meta
  API, no private Reflection invocation or UI redirect/exit mutation handler.
- shipment.issue: {delivery_id:positive integer}. Full manager_snapshot followed
  by execute_inline(id,revision,'prepare_saved') with release/dispatch nonces;
  all scanner/serial/fiscal/NP workflow stays native. Never raw stock delta or
  direct issue_delivery. Posted proof is recorded_needs_review even when native
  preparation succeeds; physical NP acceptance is NOT claimed.

GET /orders/{number}/documents/{document_id}/pdf is a fixed authenticated read.
Exact saved linkage/type, native edit_post/manage rights and issued/paid invoice
or issued delivery required. Native public download methods receive server nonce,
not a cookie-dependent admin URL. View/stamp/query overrides are refused. Backfill
metadata writes are intercepted and fail redacted; rendering temp/font cache is
allowed. Native PDF stream inherits private no-store headers. No PDF business
POST or real customer PDF was requested for tests.

## Journal, revisions and ownership

All domain POSTs use the existing unique INSERT IGNORE durable UUID claim,
actor/order/payload HMAC, native shared order mutex, editor lock, revision/pin
recheck, pending before first write, terminal readback and no native repeat.
GET journal never invokes native. Known document ID is included in the terminal
journal/result. Unknown/interrupted/partial or terminal-save failure must be
reviewed using the SAME UUID; do not create a replacement UUID to retry.

Revision includes fixed order fields plus ALL bounded linked invoice/delivery
metadata, timestamps, editor locks, ownership option, relevant stock rows and
exact operation/payload. Up to25 linked invoices and25 deliveries,50 SKUs;
stock schema guard precedes projected SELECT. It is not a SQL transaction/CAS
around native COMMIT. Native shipment independently validates its fresh release,
scanner and fiscal/NP revision before its own mutations.

Native REST responsibility_context_is_manual is false. No admin context is
simulated, and technical user is not assigned as manager. Keep native claim path
and verify ownership option/manager metadata unchanged. An empty native claim
return is normal. Reservation rejects installment states before any mutation;
its bounded native-format log/last_action/at/user and final stage/until are read
back. Unexpected ownership change => unknown, no retry.

## CLI

python3 -m scripts.operations document-snapshot --number TKD-... < spec.json
where spec is {"operation":"reservation.extend","payload":{"hours":48}}.
Create/save UUID with new-id, build the six-field explicit intent using returned
order ID/revision, then execute --confirm-execute < intent.json exactly once.
CLI persists local intent digest/UUID, consults server journal before one POST,
fsyncs submitting before network; interrupted submissions never blindly retry.
Use journal --operation-id UUID and reread snapshot/details to reconcile.
All defaults are redacted; no customer data in journal/log/Git.

python3 -m scripts.document_pdf --number TKD-... --document-id ID
saves a private0600 PDF under ignored exports/ by default. No redirects, cookies,
credential logging or overwrite; exact managed-proxy TLS host, application/pdf,
no-store, PDF magic and10MiB bound verified. Share the authorized file through
owner-controlled artifact UI, not a public converter or admin nonce link.

## Review limitations / remaining validation

Synthetic tests verify gateway boundaries, not actual WordPress/native writes.
Native UI delivery numbering does not expose an atomic shared-number allocator.
Candidate serializes cloud allocations by seller/year and reads back uniqueness,
but the supplied create_from_invoice UI source does not acquire that same lock.
Independent review must decide common UI locking/unique-number enforcement before
approving live delivery.draft under concurrent native UI use. Do not interpret
an ambiguous/partial allocation or sequence write as safe to retry.

Shipment preparation is distinct from carrier physical acceptance. Complete
invoice/draft results verify the document, not a promise of all downstream stock
synchronization. Deferred payment, direct stock changes, split invoice flows,
bank attestation and item editing remain unsupported.
